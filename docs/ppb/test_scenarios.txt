1.  How To Use This Document
Each scenario in this document is a self-contained test case for one or more subsystems of the Phase 1 Persistent Project Brain pipeline. The scenarios are organised into eight groups corresponding to pipeline stages. Within each scenario, five fields are provided:
Input Prompt: the exact input to provide — either a developer message typed into the CodeMind chat, a system trigger, or an evaluation harness command.
Context / State: the precondition that must be set up before running the scenario — the project, the current state of the knowledge graph, and any active configuration.
Expected Output: what the system must produce — nodes written to Neo4j, facts stored in PostgreSQL, log entries, API responses, or developer-visible answers. Use this as the pass/fail criterion.
Headroom Check: what to verify specifically about the Headroom compression layer at this point in the pipeline. Every scenario includes this field because Headroom must be verified across the entire pipeline, not only in Group G.
Note (where present): implementation details, acceptance criterion references, or edge case warnings.

Scenarios marked with "CRITICAL" in the Headroom Check field are the highest-priority Headroom tests. S-136, S-140, S-143, S-146, S-147, S-151, S-156, and S-164 are the eight critical Headroom tests. All must pass before Phase 1 is considered complete.

Acceptance Criteria Reference
Ref
Acceptance Criterion
AC-1
A conversation with tech stack, architectural decision and constraint produces correctly categorised, deduplicated facts with complete metadata.
AC-2
Non-engineering conversation produces zero stored memories.
AC-3
Reopening the same workspace retrieves its memories. Opening a different workspace retrieves none of them.
AC-4
Global developer preferences are available in every project without appearing in project-scoped knowledge.
AC-5
A contradicting fact triggers developer confirmation. Superseded memory archived. Both remain queryable.
AC-6
A request reaches the model with relevant memories injected automatically. Developer attaches nothing.
AC-7
Every memory operation is performed by the Project Brain tool in claude-code/src/tools via standard dispatch.
AC-8
Every request reaching the model passes through Headroom as its final stage, after injection, on every request.
AC-9
Historical questions answered from graph with citations to source memory records.
AC-10
Extraction accuracy and retrieval relevance measured against evaluation dataset and reported.
